# Web API performance: first bounded experiment

Base: main `c13183989f47d1ee1d797151b81a1e36d5fb48a4` (includes merged streaming PR427). Deliver separately on `perf/web-api-e2e-20260926`; do not reopen or modify PR427.

Scope: real HTTP calls used by the Modern dashboard and logs pages. Inspect actual routes and calls before choosing query changes. Preserve authentication, cross-user admin behavior, user isolation, filters, dates, stable ordering, counts, pagination, JSON envelopes, trace availability and post-write freshness. Existing cursor APIs are not to be reinvented. No production data or credentials; all large data is deterministic local fixture data.

Build an opt-in end-to-end workload against an actual gateway with a fresh seeded database, realistic payload sizes and enough log history to expose query costs. Include user/admin endpoints and unauthorized cases. Check complete deterministic results against a fixture oracle, not only HTTP 200. Include cold and repeated requests, page/deep-page and selective filters where supported. Capture per-request latency distributions, successful throughput and gateway CPU/RSS separately from load-generator resources. Keep all baseline/candidate request histories and hashes. SQLite results are scoped to SQLite; retain model compatibility tests for MySQL/PostgreSQL and make no backend-general speed claim without measurement.

First measure baseline. Profile CPU/allocation separately from timing; inspect SQL/query plans rather than assume CPU saturation is always attainable for DB-bound requests. Preserve existing GC, logging and auth. Admit one narrow optimization mechanism at a time; avoid a stale cache as a substitute for query efficiency. Run five alternating baseline/candidate pairs with the same fixture and bounded concurrency. Declare endpoint workloads and acceptance rules before candidate timing: material targeted median benefit must be repeat-consistent; reject correctness failures, dropped requests, material regressions in control endpoints or excessive resident growth. Do not claim browser paint or production capacity from server-local HTTP metrics.

Remote access note: the initial branch-only read-only build workflow packages exact source, vendor dependencies and a baseline binary so the isolated working environment can run real tests. It contains no secrets or deployments and is removed before delivery; it is not a performance benchmark or a relaxation of required CI.
