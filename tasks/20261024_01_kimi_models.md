## Problems reproduced before the fix

and ran:

```sh
go test -count=1 -run 'TestMoonshot(Current|K31)' ./relay/adaptor/moonshot
```

The command exited 1 with four failing top-level tests and 34 failing subtests:

1. Both `kimi-k3.1-pro` variants were absent from discovery and native pricing.
2. Their Chat reasoning efforts were discarded as unknown-model metadata, and

   normalized buckets; it does not reproduce or qualify native receipt parsing.

## Known accounting boundary

Kimi's nested `prompt_tokens_details.cache_write_tokens` and response TTL headers
are not normalized by the existing shared response parser. Default 5m writes
cost the normal input rate, so treating those tokens once as uncached input
preserves their total charge. Native 1h writes can still be undercharged; adding
correct tariff metadata does not implement their receipt handling. The audit
and K3 descriptions state this limitation explicitly. A receipt-normalization
change needs separate JSON/SSE and conversion-path coverage.
