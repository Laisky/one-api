# OpenAI catalogue update — 2026-10-26

This review follows the October 13 native OpenAI catalogue correction
([MODELS_20261013.md](MODELS_20261013.md)). The only newly published native model
ID verified for addition on October 26 is `gpt-6.1-terra`. The existing
`gpt-6-astra`, `gpt-6.1-sol`, `gpt-6-sol`, and `gpt-6-luna` definitions are
retained with their previous pricing and request semantics.

## Verified model contract

`gpt-6.1-terra` was announced on October 26, 2026. It provides a 1,050,000-token
context window and 128,000 maximum output tokens. Text and image inputs produce
text outputs; the model does not support audio or video input/output. Supported
`reasoning.effort` values are `none`, `low`, `medium` (default), `high`,
`xhigh`, and `max`. The model card documents function calling and structured
outputs and advertises web search and other Responses API tools. Native
Chat Completions is supported for tool-free calls, but tool calling requires
Responses. The existing OpenAI adaptor already converts normalized Chat
Completions and Claude Messages requests to Responses and preserves the
resolved upstream model's reasoning metadata.

Only `gpt-6.1-terra` is listed as a model snapshot on the official card.
No `gpt-6.1-terra-2026-10-26` snapshot, `gpt-6.1` alias or service-tier-specific
model ID was invented.

## Standard pricing

Prices in USD per million tokens, before service-tier or regional adjustments:

| Input token count | Input | Cached input | 30-minute cache write | Output |
| --- | ---: | ---: | ---: | ---: |
| 0–272,000 | 1.00 | 0.05 | 1.25 | 5.00 |
| 272,001+ | 2.00 | 0.10 | 2.50 | 7.50 |

The long-context surcharge is selected by **input tokens alone**, and applies
to the entire request rather than only tokens beyond 272,000. A large output
alone does not trigger the tier. Cached input is 5% of uncached input. The model
card also advertises a 12-hour cache-write option at $2.50 per million tokens
at short context; this change does **not** add a cache-retention request selector
or a new billing field for that optional tier. `CacheWrite5mRatio` is the
repository's existing legacy name used for GPT-6's documented standard 30-minute
cache-write tariff; this patch follows the current metering representation
without changing its semantics.

The separate Batch/Flex, Fast, Ultrafast, regional and other service-tier
prices are **not** silently applied by this catalogue change.

## Backward compatibility and exclusions

- This is an additive native OpenAI model entry. Existing IDs, pricing,
  channel/user overrides, mappings, credentials and historical lifecycle
  annotations are unchanged.
- Azure and reseller model deployment and availability are not proven by an
  OpenAI model card. The current Azure fallback catalogue and Azure-specific
  routing policy remain unchanged; a published native OpenAI ID is not
  confirmation of an Azure deployment or an Azure-specific tariff.
- No live-provider account entitlement, paid API call, production billing
  reconciliation, full multimodal request qualification, or performance claim
  is inferred from metadata or unit tests.
- GPT-6 Luna's separate Decisions API and GPT-Live's transport/metering remain
  out of scope; neither is unlocked by an unrelated catalogue addition.

## Behavioral regression plan

The tests are committed ahead of the implementation so their missing-catalog
and fallback-pricing failures can be reproduced on the unmodified baseline.

- `adaptor_gpt61_terra_test.go`: public discovery, numeric prices, modalities,
  independent provider catalogues, all reasoning efforts, legacy `minimal`
  normalization, invalid-effort fallback, and real mapped Chat/Claude/Responses
  request transformation and tool-safe endpoint choice.
- `gpt61_terra_pricing_test.go`: the actual billing resolver at 271,999,
  272,000 and 272,001 input tokens, including max output, all cache rates,
  full-request tier selection and retained default rates.
- Existing `adaptor_gpt61_sol_test.go`, `gpt61_sol_pricing_test.go`,
  `adaptor_gpt6_sol_luna_test.go` and `catalog_october_invariants_test.go`
  remain unchanged as backward-compatibility controls.

Recommended qualification on the repository's Go 1.27 toolchain:

```sh
go test -race -count=1 -p=2 ./relay/adaptor/openai ./relay/adaptor ./relay/pricing
go vet ./...
make test-quick
```

Passing those tests requires actual execution evidence; an unexecuted command is
not reported as a pass. Full database, frontend, integration and live-provider
qualification are separate, optional manual stages under the repository's
existing testing policy.
